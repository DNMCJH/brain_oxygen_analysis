# fNIRS 实时脑血氧分析系统 — 项目现状报告

> 更新日期：2026-04-30

## 一、项目概述

本项目的目标是构建一套**实时脑血氧分析系统**，从头皮传感器采集近红外光信号，经过 MCU 预处理和帧封装，传输到 RK3588 开发板上完成信号解析、血氧浓度计算和 Transformer 神经网络推理，最终实现对脑区血氧状态的实时分析。

总预算不到 1 万元。

## 二、系统架构

### 数据流总览

```
头罩(传感器+光源)
       │
       ▼
   ADC (SPI总线)
       │
       ▼
   MCU ──── 控制光源发射区域
    │         控制ADC采集通道
    │         SPI数据 → 串口帧格式转换
    │
    ▼ (UART)
  RK3588 (Linux + NPU)
    │
    ├── Pipeline 1: 串口帧解析 → 光强数据 + 时间戳
    ├── Pipeline 2: 光强 → HbO/HbR 浓度转换
    └── Pipeline 3: HbO/HbR → Transformer 网络推理
```

三条 Pipeline 在 RK3588 上**并行运行**。

### 硬件组成

| 组件 | 说明 | 状态 |
|------|------|------|
| 头罩 | 12 探测通道 + 4 光源（730nm/850nm 双波长） | 已完成 |
| 信号放大器 | 放大传感器微弱信号 | 已完成 |
| ADC | 模数转换，SPI 总线输出 | 已完成 |
| MCU | 光源控制 + ADC 采集 + 帧封装 + UART 发送 | 硬件就绪，固件未写 |
| RK3588 开发板 | ARM + NPU，运行 Linux | 已购入，网络已调通 |

### 探头布局

```
CH6   CH5   CH4   CH3   CH2
CH12  [L1]  [L2]  [L3]  [L4]  CH1
CH11  CH10  CH9   CH8   CH7
```

- 12 个探测通道（CH1~CH12）分布在前额叶区域
- 4 个光源（L1~L4）位于中间排，每个光源含 730nm 和 850nm 两个灯泡
- 特殊通道：CH13（全周期标记）、CH15（切换周期标记）

## 三、已完成的工作

### Phase 1：离线数据分析（已完成）

基于一份 38,692 采样点 × 16 通道的实测数据（Data.xlsx），完成了：

1. **双波长信号混叠检测**
   - 发现 12/16 通道存在双波长交替混叠
   - 不同通道的交替周期（run length）从 2 到 19 不等
   - 周期长短与该通道接收的光源数量相关

2. **信号解复用（Demux）**
   - 基于正负翻转边界检测，将混叠信号拆分为波长 A 和波长 B
   - 线性插值补全缺失点
   - 分离后信号平滑度提升 3~10 倍

3. **自动化处理工具**
   - CLI 工具：`python -m src.main <data.xlsx>`
   - 输出：分离后的 CSV + 通道分类表 + 可视化图表
   - 代码模块化：config / loader / demux / visualize / main

4. **分析报告**
   - 详细记录了设备结构、问题发现、解决方案和待确认事项
   - 见 [docs/report.md](report.md)

## 四、待完成的工作

### Phase 2：MCU 固件（未开始）

| 任务 | 说明 | 难点 |
|------|------|------|
| SPI 驱动 | 读取 ADC 数据 | SPI 时序配置、DMA 传输 |
| 光源控制 | 按时序驱动 4 个光源的 8 个灯泡 | TDM 时序精度 |
| ADC 通道切换 | 控制采集哪个探测通道 | 与光源时序同步 |
| 帧格式封装 | 将采集数据打包为固定格式 | 帧协议设计 |
| UART 发送 | 将帧数据发送给 RK3588 | 波特率、流控 |

技术栈：C/C++，裸机或 RTOS

### Phase 3：RK3588 数据管线（未开始）

三条并行 Pipeline：

**Pipeline 1 — 串口帧解析**
- 从 `/dev/ttyS*` 读取 UART 数据流
- 按帧协议解析：校验、拆包、提取光强值和时间戳
- 技术选型：C（性能优先）或 Python `pyserial`（开发效率优先）

**Pipeline 2 — 光强 → HbO/HbR**
- 双波长信号分离（Phase 1 的 demux 算法可直接复用）
- 修正 Beer-Lambert 定律（MBLL）计算 HbO 和 HbR 浓度变化
- 需要确认：消光系数矩阵、光程因子（DPF）、源-探测器距离

**Pipeline 3 — Transformer 推理**
- 将 HbO/HbR 数据转换为模型输入格式（tensor）
- 调用 RKNN 接口在 NPU 上运行推理
- 输出分析结果
- Transformer 网络已在 RK3588 上跑通

**并行架构设计要点：**
- 三条 Pipeline 需要独立运行，互不阻塞
- Pipeline 1 → 2 → 3 之间通过共享内存或消息队列传递数据
- 可选方案：`multiprocessing` + `Queue`、ZeroMQ、共享内存 + 信号量

### Phase 4：系统集成与联调

- MCU ↔ RK3588 串口通信联调
- 端到端数据流验证
- 实时性能测试和优化
- 异常处理（丢帧、超时、数据校验失败）

## 五、关键风险和待确认事项

### 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 串口帧协议未定义 | 阻塞 Pipeline 1 开发 | 需学长尽快确定帧格式 |
| MBLL 参数未知 | Pipeline 2 无法输出正确的 HbO/HbR | 需确认消光系数、DPF、源探距离 |
| 实时性不足 | 数据积压、推理延迟 | 性能关键路径用 C 实现，Python 做胶水层 |
| MCU 与 RK3588 时钟不同步 | 数据时间戳漂移 | 帧内嵌时间戳 + 定期同步 |

### 待学长确认

1. **帧格式协议** — MCU 发给 RK3588 的每一帧长什么样？（帧头、数据段、校验、帧尾）
2. **波长 A/B 对应关系** — 正值段和负值段分别对应 730nm 还是 850nm？
3. **采样率** — 每秒采集多少个点？
4. **光源发射时序** — 4 个光源 × 2 波长的具体发射顺序
5. **Transformer 模型输入格式** — 需要什么 shape 和数据类型的 tensor？
6. **CH0 和 CH14 的用途** — 额外探测器还是参考通道？
